고객 사례 표와 그 집계(예: "투자자 겸 고객 N건")를 검증할 때 쓰는 방법이다.

- **집계는 표 행마다 다시 센다.** 표 행을 확인됨 / 추정 / 제외 세 칸으로 나눈 뒤 세고, 본문의 건수와 같은 행 번호 목록이 맞는지 본다. 목록(예: 4, 6, 9, 12, 14, 17, 21)과 본문 나열(6개)이 어긋난 사례가 있었다.
- **투자자 ≠ 고객.** 표의 투자자가 다른 회사일 때(NVIDIA는 Skild 투자자, 고객은 Foxconn) 그 행은 "투자자 겸 고객"에서 뺀다. 유통 채널(住友商事)은 고객과 구분해 따로 센다. 고객 관계가 `추정`이면 확인 건수에서 뺀다.
- **"N건" 대 "행 수".** 표 행이 공급사 기준인지 고객 기준인지 본다. 고객명 미공개 행, 한 행에 여러 고객이 있는 행이 있으면 "N건"은 과장이다.
- **인용 번호가 맞는 파일인지 확인한다.** 이 프로젝트에서 자주 틀린 패턴: 수치가 다른 파일(예: 16개 나사 → skild-abb-ur-foxconn, Q4-17이 아님), 기사 수치를 1차로 표시(GXO 10만 토트는 2025-11 기사, 1차 Q4-3 아님). 출처 목록에 없는 reference 파일을 근거로 쓰면 "누락".
- **research/ 파일을 소스로 인용하면 "누락"으로 본다.** 인용 소스는 reference/에 있어야 한다 (Q4-16 PI 사례가 이 경우였다).
- **따옴표 안 문구는 원문과 글자 단위로 맞춘다.** 의역을 인용처럼 쓴 사례가 있었다.
- **"목록에 없는 세부 작업명"** (접시 담기, 부품 피킹, 조립 키트 등)은 원문에서 찾지 못하면 확인불가다.

**Why:** Q4 검증에서 "7건" 집계가 NVIDIA(투자자, 고객 아님)와 KDDI(고객 관계 추정)를 포함하고, 본문 나열과 목록이 달랐다. 두 가지 모두 원문 대조 없이는 안 잡힌다.

**How to apply:** 투자 관계 집계, 고객 수, 표의 건수 주장을 검증할 때 먼저 적용한다. 수치 확인은 reference/raw/를 find.py로 검색한다 (raw는 source-read로 저장된 원문이다).

## 도구 함정 (이 세션 기준)
- Grep 도구가 이 세션에 없었다. 검색은 Bash `grep`이나 find.py를 쓴다.
- zsh에서 `echo ====`는 "=== not found"로 실패한다. 구분선은 `echo "--- 이름"`처럼 쓴다. 이 실패 뒤로 체인이 끊겼다.
- find.py는 `'키워드1|키워드2'` 정규식으로 여러 파일을 한 번에 본다. 여러 파일을 `;`로 이으면 중간 실패 뒤에도 실행된다.
