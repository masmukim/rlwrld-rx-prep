B1(candidates.md) fact-check에서 나온 실수 유형. 다음 문서에서는 처음부터 피한다.

- arXiv API의 `max_results=10`은 상한이다. 건수를 쓰려면 응답의 `opensearch:totalResults`를 쓰고, 초록을 몇 건 열었는지 함께 적는다. "대표 과제" 같은 평가는 목록만으로 쓰지 않는다.
- 1차 소스가 자기 회사 사실만 말하면(예: Amazon Vulcan) "경쟁이 가장 치열", "전문 업체 다수"에 그 소스를 달지 않는다. `추정`과 근거를 따로 적는다.
- 회사 보도자료의 "운영 중"을 "대부분 처리"로 키우지 않는다. 운영 방식(텔레오퍼레이션인지 자율인지)을 그대로 옮긴다 (Telexistence 사례).
- 기사 속 비중(%)은 분모를 계산해 확인한다. 맞지 않으면 비중은 빼고 `확인필요`.
- 논문 수치는 어느 버전(v1/v3) 초록인지 적는다.
- 민감도 시나리오를 결론에 요약할 때 바꾼 가중치를 모두 적는다(한 항목만 바꾼 것처럼 쓰지 않는다).
- 초록의 무출처 업계 서술(예: 하네스 90% 수작업)은 점수 근거 칸 자체에 "무출처, 국가·연도 없음"을 적는다.

- (Q4) 가중합 표를 쓴 뒤 행마다 재검산한다. 초안 메모의 점수(C5=4)와 표의 점수(C5=3)가 어긋나 현대차 2.55→2.45 오류가 났다. 건수(예: 투자자=고객 9건)는 표의 행 번호로 다시 센다(참고 행을 섞지 않는다).
- (Q 정정, 2026-10-09) 일본 기업 1차 소스는 일본어 원문 시제를 쓴다. 영어판 번역이 가능형(高められる)을 완료형("has been increased")으로 바꾼 사례가 있었고, 우리 문서는 이를 다시 "목표"로 바꿔 3단계로 어긋났다. 경쟁사 협업은 "공동 개발 개시 / deploying을 향해 / 배치 중"을 1차 표현 그대로 옮긴다(기사 "Automating"을 따르지 않는다). 분모가 다른 두 비율(자동화율 vs 작업장 수 비중)은 한 문장에 나란히 두지 않는다.
- 수정 모드에서 같은 파일의 Edit는 순차로, 다른 파일끼리는 한 턴에 병렬로 보냈더니 충돌 없이 끝났다. 정정 표시 개수를 grep -c로 세서 반환에 적으면 검증이 쉽다.
