B2 공정 분석은 "요소 작업별 RFM 우선순위 점수 + 예비 회수 기간 표"를 넣으면 결론이 선다.
**Why:** 2026-10-07 하네스 B2에서 작업 3개(프리블록·레이업·테이핑)의 점수 차가 0.2점 이내라 단일 공정 대신 2트랙 PoC(빠른 성과 트랙 + 손 필요성 검증 트랙)를 근거 있게 제안할 수 있었다. 예비 회수 기간 표는 "로봇 속도비가 ROI의 관문"이라는 경영진용 결론을 숫자로 보여 줬다.
**How to apply:**
- 사이클 타임 공개 수치가 없으면 기사 속 "1인 하루 N개" 같은 발언을 근무 시간으로 나눠 하한을 만들고 계산식을 적는다.
- 다관절 손을 제안할 때는 그리퍼 대조군을 PoC 설계에 넣고, 반대 논거(그리퍼·모델 기반으로 푼 연구)를 같은 절에 쓴다.
- 가정값 표는 공정·인력 / 인건비 / 투자비 / 성능·운영으로 나누고 하한·기본·상한을 계산식과 함께 준다.
- 가중합은 쓰기 전에 항목별로 다시 곱해 본다(B2 초안에서 3.30을 3.25로 잘못 적었다). 민감도 문장에는 바꾼 가중치를 모두 적는다.

- (fact-check 정정 2026-10-09) 회수 식에는 소모품(다관절 손 교체비)을 처음부터 넣는다. 가정값 표에 "교체 주기"를 적어 놓고 식에서 빼면 낙관 편향이 된다. 교체비 0 / 1개 / 2개로 시나리오를 나누고 0열에 "상한 낙관"을 표기한다. 계산은 scratchpad에 짧은 .venv/bin/python 스크립트로 하고 표에 옮긴다.
- 수정 모드에서 reference/ 파일을 Edit하기 전에 Read로 현재 내용을 본다. 다른 에이전트가 이미 고쳤을 수 있다(이번에 reference 78%→76%이 선반영돼 있었다). 같은 숫자가 research/papers.md, knowledge.md에도 퍼져 있으면 반환에 위치를 적는다.
- 같은 파일에 Edit 여러 개를 한 메시지에 병렬로 보내도 충돌 없이 적용됐다(old_string이 서로 겹치지 않을 때).
- (B5 2026-10-12) openpyxl로 만든 roi.xlsx는 수식만 있고 캐시 값이 없다. 시트를 덤프해 수식을 읽고, 같은 식을 짧은 python으로 다시 계산해 메인이 준 값과 대조한다(이번엔 모두 일치. 인건비는 0.5x173.3 반올림 차이로 Q8 문서값과 0.01% 다름). 민감도 순위(NPV 폭)도 직접 재계산해야 "1·2순위 변수" 같은 문장을 쓸 수 있다.
- ROI 가정이 바뀌면 숫자가 퍼진 곳을 먼저 grep한다(결론, 5.3, 6절 사실표, 7.x, 리스크, 확인필요, B4 요약·6장·7장·8.3·8.5·9장·10장). 구 값은 지우지 않고 "구 가정(...)" 이력 블록으로 옮긴 뒤, 마지막에 구 값 grep으로 라벨 없는 잔존을 확인한다.
- 인건비·손 교체처럼 회수를 가르는 변수가 고객 자료로만 확정되면, 결론뿐 아니라 B4 KPI(교체 이벤트 기록)와 고객 요청 목록(급여대장)까지 바꿔야 문서 간 어긋남이 없다.

- (B6 2026-10-12) 프로토콜이 비공개인 벤치마크(DexBench)를 PoC에 "반영"하라는 요청은 ① 공개 형식만 차용(케이스 카드: 초기·목표·실패 조건), ② 빈칸은 우리 값, ③ "공개 형식 / 우리 제안 / 발행 측 확인" 3열 출처 표 + G0 확인 목록으로 풀면 과장 없이 끝난다. 원문 JSON은 grep -n으로 케이스 id 줄을 찾고 Read offset으로 60줄만 읽으면 충분했다. 신뢰구간·시행 예산은 scratchpad python으로 계산해 "(계산)"을 단다. 새 소절은 다음 ### 제목을 old_string으로 잡아 그 앞에 한 번의 Edit로 삽입했다(Write 거부 회피).

- (B9 2026-10-12) 민감도 결과를 문서에 옮길 때는 다른 에이전트가 보고한 단위를 다시 계산해 본다(B8 보고의 "1,561억"은 실제 약 1.56억 원이었다). 변수 순위를 쓰기 전에 상호작용도 확인한다: 손 단가 폭은 기본 시나리오에서 1.56억 원이지만 보수 시나리오에서는 4.33억 원이었다. 평가 구성을 하나 더하면 시행 예산은 "기본안(공칭만) / 상한안(전 스윕)" 두 줄로 나눠 계산식을 쓰고, 가용 시간(1교대 160시간 `추정`)과 비교해 넘치는지를 적는다. 작업이 중간에 끊긴 뒤 이어서 할 때는 `grep -c '<작업ID> 반영'`으로 이미 반영된 곳을 먼저 센다.
