# 원문 읽기

WebFetch는 작은 모델이 페이지를 **요약한 결과**만 돌려준다. 그래서 정확한 수치, 인용문, 날짜가 빠지거나 섞일 수 있다. 원문 문장이 필요하면 이 방법을 쓴다.

## 언제 쓰나
| 상황 | 도구 |
|------|------|
| 기사, 블로그 등 2차 소스를 훑어볼 때 | WebFetch (작업당 15개 안팎) |
| **1차 소스(보도자료, 공식 페이지, 공시), 논문 본문, 결과물에 인용할 수치와 문장** | **source-read** (개수 제한 없음) |
| WebFetch가 403, 빈 페이지, 이상한 요약을 돌려줄 때 | source-read로 다시 시도 |

## 절차
1. 원문 저장 (Bash):
   ```
   .venv/bin/python .claude/skills/source-read/fetch.py '<URL>' reference/raw/<reference 파일과 같은 슬러그>.txt
   ```
   - **명령은 위 형태 그대로 쓴다.** 상대 경로 `.venv/bin/python`으로 시작하고, `cd`, `mkdir`, `&&`, `for` 반복문을 붙이지 않는다. 이 형태만 권한 허용 목록에 있어서 다른 형태는 거부된다 (B1 테스트에서 반복문과 절대 경로가 거부됨). 저장 폴더는 스크립트가 만든다.
   - **URL은 작은따옴표로 감싼다.** `?`나 `&`가 든 URL을 감싸지 않으면 셸이 오류를 낸다 (B2 테스트).
   - 원문이 여러 개면 한 턴에 Bash 호출을 여러 개 **병렬로** 보낸다.
   - 출력은 `OK <경로> <줄 수> lines` 또는 `FAIL <이유>` 한 줄뿐이다.
   - 논문은 `https://arxiv.org/html/<id>`(HTML 전문)를 먼저 쓰고, 실패하면 `https://arxiv.org/pdf/<id>`를 쓴다. PDF도 텍스트로 변환된다.
2. **원문은 find.py로 검색한다.** 여러 파일을 한 번에 검색하고, 파일마다 일치한 줄을 최대 15개까지 앞뒤 1줄과 함께 보여 준다:
   ```
   .venv/bin/python .claude/skills/source-read/find.py '키워드1|키워드2' reference/raw/a.txt reference/raw/b.txt
   ```
   - 셸의 `for` 반복문, `awk`, `cd ... &&` 조합은 쓰지 않는다. 권한 목록에 없어 거부되고, 거부되면 턴만 낭비된다 (B1·B2 테스트에서 실행당 2~4회).
   - 원문 파일을 Read할 때는 **반드시 offset과 limit를 지정한다.** find.py가 알려 준 줄 번호 근처만 읽는다. 통째로 읽으면 원문을 저장한 의미가 없다 (논문은 4,000줄이 넘는다).
3. reference 파일의 `원문 발췌`에는 Grep으로 찾은 문장을 **그대로** 인용하고, 끝에 `(raw: reference/raw/<파일>.txt)`를 적는다.

## 실패할 때
- `FAIL ... 403`: 봇 차단이다. 다른 소스를 찾거나, 기사라면 같은 내용을 보도한 다른 매체를 쓴다.
- `FAIL ... only N chars`: 자바스크립트로 그려지는 페이지다. WebFetch로 시도하고, 그래도 안 되면 `확인필요`로 둔다.
- 유료 기사는 우회하지 않는다. `유료, 미열람`으로 표시하고 다른 소스로 대체한다.

## 주의
- `reference/raw/`는 저작권 때문에 git에 올리지 않는다 (.gitignore). 로컬 확인용이다.
- 원문 파일이 이미 있으면 다시 받지 않는다. 먼저 `ls reference/raw/`로 확인한다.
