# RLDX-1 공식 기술 블로그 분석: 아키텍처, 학습, 평가 조건, 한계
조사일: 2026-10-07

## 핵심 요약
- **설계:** RLDX-1은 모달리티마다 전용 스트림을 두는 MSAT 위에 Motion, Physics, Memory 모듈을 얹은 VLA이고, 학습은 Pre-training → Mid-training → Post-training 3단계다 [1][2]. 이 중 Memory·Physics는 Mid-training에서 처음 추가되므로, 시뮬레이션 SOTA 주장(RLDX-1-PT)은 두 모듈의 효과를 보여주지 않는다 [1].
- **평가 조건:** 실세계 수치는 과제당 24회 시행, 과제별 시연 40~100개 fine-tune, 과제에 필요한 모듈만 켠 결과다 [2]. ALLEX 평균 86.8%(기준선 39.1, 44.8)에는 성공률이 아닌 진행 점수(progress score) 2개 과제가 섞여 있고, 촉각은 ALLEX가 아닌 Franka 그리퍼 플랫폼에서만 쓰였다 [1][2]. 조립 공정과 가장 비슷해 보이는(본 문서 판단) Plug Insertion은 33.3%(24회 중 8회)였다 [1][2].
- **기존 문서 정정:** research/tech.md의 "RLDX-1에 RL 단계 미확인"은 틀렸다. 블로그와 논문에 post-training(교정 데이터 + RECAP 기반 RL)이 있으나 RL은 선택 사항이고 효과 검증은 전구 돌리기 1과제(자체 평가)다 [1][2]. 정정 4건, 보완 8건, 해소 2건(총 14행)은 본문 9절 표에 있다.

### 2. 아키텍처
블로그는 "모든 구성 요소는 실제 과제에서 나온 특정 실패 모드 때문에 존재한다"고 설명하고, 손재주를 5개 영역(regime)으로 나눠 각 영역을 담당하는 부품과 연결한다 [1].

| 영역(DexBench 분류) | 실패 모드 | 담당 부품 | 블로그가 제시한 근거 수치(조건) |
|---------------------|-----------|-----------|-------------------------------|
| Grasp Diversity | 다양한 파지 | 5지 손 하드웨어(사내 10종 이상 운용) + 합성·인간 데이터 | 수치 없음 [1] |
| Spatial Precision | 접촉 전 공간 추론 | 로봇 특화 VLM (Qwen3-VL 8B를 로봇 VQA로 fine-tune) | RoboCasa 57.50 → 60.92(+3.42, 시뮬 1개) [1] |
| Temporal Precision | 움직이는 물체 | Motion Module(영상 토큰 평균 풀링 + STSS) | 컨베이어 pick-and-place +37.5%p(87.5 vs N1.6 50.0, ALLEX) [1] |
| Contact Precision | 힘·접촉 | Physics Module(촉각·토크 전용 스트림, 미래 토크 예측) | 카드 슬라이드, 따르기, 플러그 삽입 등 (5.3절) [1][2] |
| Context Awareness | 진행 상태 | Memory(과거 cognition 특징 FIFO 캐시), Recovery(DAgger), Progress-Awareness(진행도 추정 VLM) | Object-in-Box 91.7%, Shell Game 91.7% [1] |

핵심 구조:
- **MSAT.** 모달리티(vision-language, proprioception, action, memory, tactile, torque)마다 전용 스트림, 초기 블록은 병렬, 후기 블록에서 joint self-attention으로 융합한다. 기존 VLA는 단일 스트림이라 "그래디언트를 지배하는 모달리티가 용량을 독차지한다"는 것이 회사의 설계 논거이며, SD3(MM-DiT)와 FLUX를 근거로 인용한다 [1]. 이 논거를 직접 검증한 비교 실험은 블로그에 없다. 행동 모델은 flow-matching DiT다 [2].
- **Cognition Interface.** VLM 입력에 학습 가능한 cognition token 64개를 붙여 VLM 출력을 고정 크기로 압축한다. 추론 속도 16.3 → 22.1 Hz(측정 조건 미기재)이고, 같은 64토큰이 Memory의 단위가 된다 [1]. company.md가 "64 cognition tokens"를 Memory 모듈로 적은 것은 부정확하다(9절).
- **Memory 창.** FIFO 캐시에 과거 cognition 특징 3개를 행동 청크 간격(H+1)으로 저장한다. 청크 길이 ALLEX 40, FR3 16 기준으로 과거 120, 48 타임스텝을 덮는다 [2]. 블로그가 "시간 단위의 긴 상호작용은 미래 과제"라고 쓴 이유다 [1].
- **Physics 스트림.** 블로그가 명시한 기능은 무게 추정(커피 따르기, 멈출 시점)과 접촉 감지(접근에서 파지로 전환) 두 가지다. 센서가 없으면 스트림이 꺼져 vision-only로 "graceful degradation"하며, 저하 폭 수치는 블로그에 없다 [1]. 논문은 ALLEX는 관절 토크만, FR3는 관절 토크 + AnySkin 촉각을 쓴다고 쓴다 [2].
- **크기.** Mid-trained 체크포인트 둘은 각 8.1B다. PT 크기는 블로그에 없고 GitHub의 6.9B와 모듈이 빠진 구성이 정합하나 이는 `추정`이다 [1][8].

### 3. 학습 3단계
| 단계 | 내용 | 규모·조건 | 출처 |
|------|------|-----------|------|
| Pre-training | 단일팔·양팔·휴머노이드 일반 조작. 공유 MSAT + 임베디먼트별 인코더·디코더, 임베디먼트 태그 무작위 드롭으로 조건부·비조건부 정책을 한 백본에 학습 | 100K 스텝, 배치 8192, 64 H200에서 약 195시간(약 12,480 GPU-시간, 계산) | [1][2] |
| Mid-training | 대상 로봇(ALLEX, FR3) 특화. Memory·Physics 모듈을 처음부터 초기화해 추가, 기존 가중치 보존, 사전학습 데이터 일부 재사용(망각 방지) | 25K 스텝, 배치 1024, 64 H200에서 15시간(약 960 GPU-시간, 계산). 새 모달리티 2K 스텝 정렬 워밍업 | [1][2] |
| Post-training | (a) 교정 데이터: 배포 후 이탈 시 교정해 새 학습 데이터로 반복 (블로그는 DAgger로 부름. 논문은 "적응형 데이터 수집"으로 서술하며 DAgger 표현은 없음) (b) 진행도 추정 VLM을 dense reward로 쓰는 RL (논문: RECAP 기반, 텍스트 VLM critic) | 과제별 fine-tune 30K 스텝(ALLEX 배치 128). RL은 "필요할 때 선택적으로" 적용 | [1][2] |

- 논문은 "거의 모든 실험을 모방학습으로 했다"고 쓴다 [2]. 따라서 5.3절 실세계 표(Table 4, 5)가 RL 적용 모델인지는 표기가 없고, 모방학습 결과로 읽는 것이 논문 서술과 맞다(`추정`).
- RL 효과의 유일한 증거: ALLEX Light Bulb Twisting(오른손 엄지·검지로 전구 돌리기). BC 1056±326 프레임, 12.7±3.0회 시도 → RECAP3 353±22 프레임, 4.1±0.3회로 약 3배 감소. 블로그의 "모방학습 대비 약 3배 빠르다"는 이 1과제 결과이고, 프레임 속도가 없어 초 단위 환산은 못 한다 [1][2].

- 블로그 주장: GR00T N1.6은 RoboCasa 시뮬 데이터를 사전학습에 포함하지만 RLDX-1은 실데이터만 썼으므로 격차는 "아키텍처와 데이터 엔진" 덕이라고 한다(회사 주장, 검증 불가) [1]. 기준선의 시뮬 학습 조건은 이번에 확인하지 못했다.
- "GR00T N1.5 대비 약 20% 학습 연산으로 SOTA 도달"은 내부 체크포인트(0.2 → 0.25 → 0.3 → 1) 궤적 비교이며 기준선은 N1.5다 [1].

#### 5.2 실세계: ALLEX 휴머노이드 (RLDX-1-MT-ALLEX)
| 과제 | 측정 방식 | pi0.5 | GR00T N1.6 | RLDX-1 | 시연 수 | 출처 |
|------|-----------|-------|-----------|--------|---------|------|
| Conveyor Pick-and-Place | 성공률, 컨베이어 속도 4종 x 6회 (S1, S4 학습, S2, S3 미학습) | 29.2 | 50.0 | 87.5 (학습 속도 100%, 미학습 75%) | 40 | [1][2] |

| Card Slide-and-Pick | **진행 점수**(밀기 0.33, 집기 0.66, 전달 1.0), 낮은 책상 높이에서만 24회 | 55.3 | 62.3 | 97.2 | 72 | [1][2] |

| 평균 | 4개 단순 평균(본 문서 검산: 39.1, 44.8, 86.8 일치) | 39.1 | 44.8 | 86.8 | | [1] |

- 블로그 서술문 "기준선은 30% 미만, RLDX-1은 거의 90%"는 같은 블로그 표와 어긋난다. 30% 미만은 컨베이어(pi0.5 29.2)와 Object-in-Box(N1.6 29.2) 각 한 칸이고 기준선 평균은 39.1, 44.8이다. 논문 결론은 "약 90% 대 약 40%"로 표와 맞는다 [1][2].
- 두 과제가 진행 점수이므로 평균은 성공률과 진행 점수를 섞은 값이다. 완주율(full success)은 따로 공개되지 않았다. 논문은 Pouring에서 "두 기준선 모두 어떤 시행에서도 전체 과제를 끝내지 못했다"고 쓴다 [2].
- 학습·평가 조건: 과제별 30K 스텝 fine-tune, **"과제별로 대상 기능에 해당하는 모듈만 켜고 나머지는 끈다"**, 머리 스테레오 카메라 1대만 사용(손목·측면 카메라 없음), 토크는 모터 전류 추정값 48축. 기준선은 공식 구현 레시피로 같은 스텝·설정에서 fine-tune했다고 한다 [2]. 모든 모듈이 켜진 단일 모델이 4과제를 푸는 결과는 아니다.
- 블로그의 대표 과제 그림은 "커피 따르기"지만 평가는 플라스틱 공이었다 [1][2].

| 평균 | 34.4 | 31.6 | 68.5 | | [1] |

- 블로그 본문은 이 플랫폼 과제를 4개(Swap Cup, Shell Game, Plug Insertion, Egg PnP)로 쓰지만 표와 논문은 6개다 [1][2].
- Plug Insertion 33.3%는 24회 중 8회다. 이항 분포 Wilson 95% 구간으로 계산하면 약 18~53%이고 기준선 20.8%(5/24)의 구간 약 9~40%와 겹친다(본 문서 계산, 근사). 이 과제의 우위는 24회 시행으로는 통계적으로 확정되지 않는다.
- 이 플랫폼에서 촉각을 쓴 "손" 실험은 없다. 엔드이펙터는 1-DoF 그리퍼다 [1][2].

#### 5.4 OpenArm + Inspire 6-DoF 손 (RLDX-1-PT, Mid-training 없음)
- 학습 시연 348개(4개 과제군), 인형 집어 상자에 넣기(Basic Pick-and-Place) 50.0%(pi0.5 41.7, N1.6 37.5). 미학습 물체 54.2% vs pi0.5 37.5%. 물체 특정(Object Grounding) 87.5%, N1.6은 33.3%로 무작위 수준 [2]. 블로그는 그래프(Figure 16)로만 제시한다 [1].
- 해석(본 문서): 6-DoF 손에서 Mid-training 없이도 전이되나, 기본 집기·놓기 성공률이 50%대다.

### 7. 한계
**회사가 명시한 한계** (블로그 6-4절) [1]
- 과제별 데이터 요구량이 다르며 어떤 과제는 상당한 post-training이 필요하다(수치 없음).
- 기억은 단기~중기 범위만 시연했고 시간 단위 상호작용은 미래 과제다.
- 사전학습 정책의 zero-shot 일반화는 "열린 방향"이다.
- video/world model 확장은 미래 과제다.

## RX 관점 시사점

### 고객 제안에서
- **평가를 KPI로 번역할 때 지표 정의를 먼저 정한다.** 이 블로그의 평균은 성공률과 진행 점수의 혼합이다. PoC 합의서에는 "완주율(전 단계 성공)"과 "단계 점수"를 분리해 쓰고, 합격 기준은 완주율로 잡는다(본 문서 제안).
- **공개 평가 규모를 PoC 설계의 하한 참고로 쓴다.** 과제당 시연 40~100개, 평가 24회, 위치 3~4조건, 과제별 fine-tune 30K 스텝이 RLWRLD 자체 평가 규모다 [2]. 24회에서는 구간이 넓어(33.3%의 구간 약 18~53%) 고객 PoC는 시행 수를 더 늘리거나 구간을 함께 보고하도록 제안한다(계산 근거 5.3절).
- **PoC 로드맵 단계 구조의 근거.** 논문의 "기본 시연 → 정책 배포 → 실패 조건 겨냥 추가 시연 반복 → (선택) RL"은 B4 PoC 게이트(G0~G3)의 후반 단계와 일치한다 [2]. RL은 효과가 1과제 자체 평가라 선택 확장으로만 둔다.
- **B3 비용 변수.** 학습 약 12,480 GPU-시간(사전) + 960 GPU-시간(mid) + 과제별 30K 스텝, 추론 RTX 5090급 PC 1대 [1][2]. 단가는 소스에 없어 AWS H200 가격 등 별도 조사가 필요하다. 고객 PoC에서 새로 필요한 학습은 과제별 fine-tune이고 사전·mid 학습은 RLWRLD가 이미 한 것으로 읽힌다(`추정`).
- **센서 선택을 PoC 변수로 둔다.** 촉각 증거는 그리퍼 플랫폼뿐이고 손 플랫폼은 토크만 쓴다 [2]. 고객 손에 촉각이 있어도 RLDX-1이 손 촉각으로 얼마나 개선하는지는 공개 수치가 없다.

### 와이어 하네스(B1·B2) 케이스에 쓸 수 있는 근거와 쓸 수 없는 근거
| 하네스 단계(case/analysis.md) | 필요한 영역 | 블로그·논문에서 가장 가까운 결과 | 근거 수준 |
|-------------------------------|-------------|----------------------------------|-----------|
| 프리블록(단자 삽입) | Contact Precision | Plug Insertion 33.3%, 24회, 그리퍼 + 촉각 | 낮음. 그리퍼 + 힘센서로 90% 이상을 보고한 연구가 있어(knowledge.md) 손의 이점이 입증되지 않음. 직접 비교 불가 |
| 레이업(전선 훑기·걸기·분기 정리) | 변형체 + 접촉 + 순서 | 변형체 케이블 과제 없음. 가장 가까운 것은 인형 집기 50%(OpenArm), 얇은 카드 집기 진행 점수 97.2 | 공개 근거 없음. PoC에서 검증할 항목 |
| 순서·누락 확인 | Memory | Object-in-Box 91.7%, Shell Game 91.7%, Swap Cup 45.8% | 중간(과제 단순). 기억 창 120 타임스텝 |
| 이동 조립판 | Motion | 컨베이어 87.5% | 하네스는 대체로 정적 조립판이라 관련성 낮음(`추정`) |

- B2 분석의 "그리퍼 대조군을 PoC에 넣는다"는 결정은 이 소스로도 유지된다. RLWRLD의 촉각 증거 자체가 그리퍼 플랫폼에서 나왔다 [2].
- case/analysis.md 120행의 Memory 모듈 매핑은 "Memory(순서 추적) + post-training 교정 데이터(복구)"로 고쳐 써야 한다(9절 3번).
- Light Bulb Twisting(엄지·검지 비틀기)은 손가락 정밀 동작의 유일한 RL 사례이고, 커넥터 체결과 같은 작업이라는 근거는 없다.

### 면접·내부 설명에서
- 한 문장: "RLDX-1은 모달리티마다 별도 스트림을 두고 Mid-training에서 기억·물리 입력을 붙인 구조이고, 실세계 증거는 과제별로 해당 모듈만 켠 24회 시행 결과다."
- 약점도 구체적으로 말한다: 진행 점수 혼합, 촉각은 그리퍼에서만, 플러그 삽입 33.3%, RL은 1과제, 블로그 서술문과 표의 불일치, 모듈 논문 저자의 RLWRLD 소속.
- RLWRLD의 강점은 평가의 투명성이다. 시행 수, 시연 수, 하이퍼파라미터, 코드, 체크포인트가 공개되어 있어 PoC에서 같은 방식으로 재현 평가를 제안할 수 있다 [1][2][8].
